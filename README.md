# B站 AI 直播小插件 · Bilibili AI Live Kit

把直播互动台、头像旁的两个文字框、弹幕接收和 AI/语音桥接放进一个独立的本机小工具。**不附带任何角色图片、动态模型、参考声线、账号凭据或聊天记录。** 使用自己的头像和声音。

这是浏览器源工具，不是 B 站官方插件，也不自动开播。直播姬/OBS 添加网页素材即可使用。

## 包含什么

- 实时弹幕：B 站 WebSocket → 内存事件 → SSE 推送到互动台，避免截图识别与 JSON 文件轮询。
- 互动台：手选、五条锁定批次、安静五秒发不足一批、插队/换序/移除，已播放项不打断；自定义游戏分区。
- 两个同宽文字框：上方游戏思路永远只显示文字，下方显示正在回答的弹幕和答案。
- 头像槽：放自己的 GIF/APNG、图片或已有网页动态模型；提供实际音频音量参数转发。**没有附赠 Live2D 模型，也不从一张图自动生成 Live2D。**
- AI 接入：自己的 AI 通过领取任务接口回答，或自行配置兼容 Chat Completions 的服务。没有内置免费模型或账号。
- 语音：兼容 `/v1/audio/speech` 的服务；完整句块预生成、单播放器串行、下一段预取。可选 Qwen3-TTS 本地适配器，不包含模型权重和声音样本。
- 配套 [Codex skill](skills/bilibili-ai-live/SKILL.md)、接口说明、隔离测试和延迟测量脚本。

## 五分钟体验界面（不连账号、不播音）

1. 安装 [Node.js](https://nodejs.org/) **22.13 或以上**，下载本仓库并解压。核心程序没有 npm 第三方依赖。
2. Windows 双击 `demo.cmd`；其他系统运行 `node server.cjs --demo`。
3. 打开终端显示的 `http://127.0.0.1:17980/console`，把终端的 **Control token** 粘进控制台。它仅用于本机控制，别发到直播画面或仓库。
4. 演示弹幕 →「只回文字」→「领取下一条」→ 填回答 →「提交回答」。打开「画面预览」即可看到下方框更新。
5. 在「游戏思路」输入公开的操作计划，上方框立即更新，**不会合成语音**。

第一次启动只会在本机生成 `data/keys.json`；保存设置才生成 `data/config.json`。不要分享 `data/`、`.env` 和 `user-assets/`。演示弹幕是合成测试数据，不代表已连上真实房间。

## 接入自己的直播间

1. 复制 `.env.example` 为 `.env`，如 B 站接口要求登录，在自己的电脑填写自己的 `BILI_COOKIE`。程序不读其他软件的 Cookie，也不代登录。Cookie 过期、风控或接口变化会导致接收失败；控制台会显示连接状态。
2. `start.cmd` / `npm start`。打开控制台配置，填写 `roomId`，保存后点「连接直播间」。支持短房间号解析。
3. 用自己的直播间发一条测试弹幕，确认进入左栏，再手动加入待答。这一步通过才算真实接收验收。**它只接收，不发 B 站弹幕。**
4. 自动收集默认关闭，`liveOnly` 默认开启；启用前先确认模型与声音配置。下播不会自动收集。手动选择可用于离线调试。

当前接收使用 web-client 通道，不是 B 站开放平台授权 SDK。参考协议项目：[blivedm](https://github.com/xfgryujk/blivedm)。平台接口没有永久可用保证；请遵守平台要求。登录失败时不绕过风控。

## 放进直播姬 / OBS

添加浏览器/网页素材：`http://127.0.0.1:17980/overlay`。默认宽 360、高 660（头像 360、每框 150），可在配置中修改。背景透明；两个框的颜色、字号、高度可调，不包含游戏分区装饰。

头像按 [AVATAR.md](docs/AVATAR.md) 接入自己的资源。开启语音后，另加控制台「独立语音播放器」的完整链接，并开启该网页源的音频输出；**只开一个播放器**，头像画面源不重复发声。浏览器阻止自动播放时，打开播放器页点「允许播放」。实际直播收音仍需短录回放验收。

## 接自己的 AI 和声音

- **外部 AI/技能模式**：把 `skills/bilibili-ai-live` 复制到自己的 Codex skills 目录，按 `docs/API.md` 调用。skill 是操作说明，不能代替常驻模型、模型额度或开播授权。
- **自动模型模式**：配置 `llm.url/model/system`，在 `.env` 填 `LLM_API_KEY`（本地服务无密钥可留空），再设 `llm.enabled=true`。所选分区、当前弹幕和最新游戏概要会发给此服务；费用由使用者的服务产生。
- **语音模式**：配置 `voice.url/model/voice`，需要时填写 `TTS_API_KEY`，再启用 `voice.enabled`。声线由自己的 TTS 服务提供。Qwen3-TTS 方案见 [VOICE.md](docs/VOICE.md)。不加未经要求的降调、变速、混响或叠音。

`text` 模式不合成语音；`note` 模式不调用模型、不合成语音，只写本机所选分区的笔记。观众建议不会自动变成长期记忆。游戏接口需要自己单独接入，本项目只接收已获得的游戏概要/状态。

## 速度与验收

运行 `npm test`，再运行 `npm run benchmark`。测量结果写在被忽略的 `data/benchmark.json`。

这里的低延迟设计是直接推送、内存队列、避免重复播报，以及完整句块预取，**不是零延迟承诺**。控制台指标区分平台时间戳到本机接收、AI回答、每句 TTS、排队到播放。`sourceToBackendMs` 受 B 站字段精度和双方时钟影响；本机 SSE benchmark 不包含 B 站公网、AI、GPU模型或音频设备延迟。

语音先要有回答，再合成完整句块；当前适配器不是模型 token 级流式播放。第一句长、服务冷启动或显存不足都会变慢。请分别完成：真实弹幕、AI回答、TTS首段、单播放器、直播收音这五项验收。

## 边界与版本

默认仅监听本机；控制 API 要令牌，播放 API 使用独立受限令牌。聊天内容永远是数据，不能授权电脑操作。默认过滤仅处理显式链接、简单危险指令与短时重复，**不能保证识别所有广告、暗号或不适合直播的话题**。请在自己的角色规则中设置话题范围，必要时保持手选。

当前为 **0.1.0 初始公开版**：核心和协议解析可隔离测试；每位使用者仍要用自己的 B 站登录、模型和声线实测。没有把原作者的直播会话、头像、语音、游戏战绩或游戏执行接口打包进来。
